# 录放台 · 给 Agent 直接调用的浏览器操作录制与回放

在程序打开的受控浏览器里操作一次网页，录放台把操作整理成**可审阅、可编辑的工作流**；之后点一下、
或由任意 Agent 调一次接口，就按同样的步骤自动重放。单进程、单窗口、无系统边框，数据全部留在本机。

## 启动

- **封装版**：双击项目根目录的 `录放台.exe`（就在 `recorded-automation\` 这一层）。
  同级 `ms-playwright\` 是自带浏览器引擎（约 420MB），整个文件夹可以整体拷到别的电脑；
  该目录被删时程序自动改用本机已装的 Microsoft Edge；两者都不可用时，界面会给出修复指令。
- **源码版**：`python -m ra.main`（依赖 `playwright`、`jsonschema` 与可用的浏览器引擎）。

## 它是一个桌面程序，不是一个网页

窗口没有系统边框：Chromium 自己在客户区顶部画的那条约 76px 的标题条（标题栏 + 自动化信息条）被整段
顶到屏幕之外，界面上只有一条程序自绘的标题条 —— 应用标记、名称、当前界面、运行状态，右侧是
**最小化 / 铺满工作区 / 全屏 / 关闭**四个按钮，配色与界面同一套。任务栏与 Alt-Tab 里显示的是本程序的
名字和图标（图标随界面一起打包，不是浏览器图标）。

| 形态 | 说明 | 怎么切 |
| --- | --- | --- |
| 停靠无边框（默认） | 内容顶边贴住屏幕工作区顶边，标题条整段出屏；左右可移动，上下拖改变高度，四条边可缩放 | 标题条拖动 / 边缘手势 / 设置页 |
| 全屏 | 占满整块显示器，同样没有系统标题栏 | 标题条第 3 个按钮，或设置页 |
| 自由窗口 | 可拖到屏幕任意位置，代价是顶部会露出浏览器自带标题条；此时界面不再重复画自己那条 | 设置页「界面窗口形态」 |

这条边界是引擎给的，不是没做：Chromium 只在进入全屏时不画那条标题条，清掉 `WS_CAPTION` 这类样式位
无效（实测画面里那条仍在），`SetWindowRgn` 想裁掉它也被 DirectComposition 忽略（返回成功、画面不变）。
所以程序的做法是**把它顶出屏幕**，
并用屏幕像素反查标定它到底多高 —— 启动时页面最上面画一条标记色横条，看它出现在屏幕第几行，
量完再摆正，最后再复核一次：标记条必须正好落在屏幕第一行（`drift=0`）。量错会让界面顶部被切掉几十像素，
所以这一步不靠几何差值猜（实测会把 76px 读成别的值）。当前实测数字写在设置页「当前窗口实测」那一行。

形态与位置尺寸都会写进本机 `settings.json`，下次启动保持原样。首次启动是空的：这里不放示例数据，
工作流和运行记录都来自你自己的操作。

一条要如实说明的限制：**无边框形态下顶边被钉在工作区顶边**（这是把标题条藏起来的必要条件），
所以标题条拖动只改变水平位置，改高度请拖下边缘。而 Chromium 会不定期把自己记住的窗口位置刷回来
（实测：把窗口从 x=340 摆到 x=400 后，它又回到 340）。程序不与它抢水平位置：只在浏览器标题条
重新露出来时补位，保证无边框形态不被破坏。最大化、全屏、最小化、关闭、拖边缘改尺寸都是稳定的；
想稳定地换个横向位置，最可靠的做法是切到「自由窗口」再拖（那条形态下位置由你自己拿住）。

## 使用流程

1. **工作台**（`Alt+1`）：顶部四张统计卡显示工作流数、最近运行成功率、待填秘密引用、当前浏览器引擎，
   以及 Agent 接口是否在线。下方「三步就能用起来」按你现在的真实进度标出已完成 / 下一步该做什么。
   填入页面地址 → `Enter` 或点「开始录制」。
2. **录制中**（`Alt+…`随界面）：左侧是受控页面的实时画面，右侧是正在生成的候选步骤；连续输入自动合并成
   一次 `fill`，其他来源的事件被丢弃并列出原因；密码类输入只记录"这是敏感字段"，不记录内容。
3. **停止并审阅**：逐条检查步骤。每条列出候选定位器（`role → label → test_id → text → css`）和它们在
   当前页面的匹配数量；多匹配或找不到的会被标出来，可以改定位值、换候选、调顺序、删步骤、补完成条件。
   「重新校验唯一性」按当前打开的页面重新数一遍匹配数。多匹配的步骤摊开候选列表供点选，
   找不到目标的步骤直接写出三步修复出路（换定位值 → 重新校验 → 或改完成条件/删掉这一步）。
   审阅页的「试运行草稿」按当前草稿立即跑一次，不用先保存。
4. **校验并保存**（`Ctrl+S`）：先过 JSON Schema（`ra/workflow.schema.json`），再过执行语义
   （步骤 ID 唯一、`start_url` 与 `origin` 同源、`role` 定位器带可访问名称、`start_url` 不含令牌参数）。
   有阻塞项时保存按钮不可用。保存时若秘密库还缺引用值，会直接跳到秘密库那一屏并列出缺的引用名。
5. **运行**：受控浏览器打开 `start_url`，按步骤执行；运行页显示步骤时间线、阶段日志与结果分类。
   停在「失败」或「已取消」时（这两步的动作都没发出去过）会出现**从失败步重试**：只跑剩下的步骤，
   已执行过的步骤绝不重跑，界面会写明本次跳过了几步；「未确认」不给这个按钮，只给人工检查清单。
6. **运行历史**（`Alt+2`）：每次运行的事实日志，点一行回到那次的结果页；工作流被删过会标出来。
   日志有上界：单份 2MB 到线就整份轮转、留 2 份归档；被挤出去的最旧一份会删除，
   而这件事会写在页面上（「运行日志超过 2000000 字节……已删除」那一行）与 `ra.status` /
   `ra.run_history` 的返回里 —— 列表变短了一定要同时说清为什么。
7. **秘密库**（`Alt+3`）：工作流里只存引用名。填真实值后按当前 Windows 账户加密保存在本机，
   每行显示该引用被哪些工作流使用；缺值时运行会被直接拦下并指出引用名。
8. **Agent 接口**（`Alt+4`）：见下一节。
9. **设置**（`Alt+5`）：默认超时、无界面运行、代理、窗口形态、Agent 接口开关、清空浏览器登录态、
   打开数据目录、重看上手引导、运行端到端自检。

## Agent 接口：程序本身就是那个后端

这个程序的主要用途就是**被 Agent 直接调用**。接口跑在界面同一个进程里，共用同一套会话与存储，
所以 Agent 发起的录制、剪辑、运行会实时反映在界面上，也不会和界面抢同一个浏览器档案目录。
契约见 `personal-agent-hub/docs/AGENT_API_STANDARD.md`，逐项说明在 `agent/README.md`，
界面里「Agent 接口」那一屏把端点、工具清单和可直接抄走的接入片段都列出来了。

```bash
# 程序开着的时候，端点就已经在听了（默认 8795，被占自动 +1，实际地址写在 agent/.endpoint）
curl -s http://127.0.0.1:8795/api/health
curl -s http://127.0.0.1:8795/api/agent/tools
# 写操作（非 GET）要带本机共享令牌；令牌由程序启动时写进 %LOCALAPPDATA%\RecordedAutomation\agent-token
TOKEN="$(cat "$LOCALAPPDATA/RecordedAutomation/agent-token")"
curl -s -X POST http://127.0.0.1:8795/api/agent/tool -H 'content-type: application/json' \
     -H "x-agent-token: $TOKEN" -d '{"tool":"ra.status","input":{}}'
node agent/mcp-server.mjs        # MCP stdio 桥：自动读令牌文件，本机合法 Agent 不需要手工传
python agent/server.py           # 不想开界面时，也能单独起一个同契约的服务（同一把令牌）
```

**谁能调用**：只监听 127.0.0.1，并且每个请求都过 `ra/localguard.py` 的四道闸门 —— `Host` 必须是回环名
（挡 DNS rebinding）、`Origin`/`Referer` 不是回环就拒、所有非 GET 必带 `x-agent-token`、
任何响应都不发通配 CORS（网页连预检都过不去）。这一条是 2026-10-05 验收返工补的：
补之前用户访问的任意网页都能驱动全部 25 个工具。判据、令牌位置与手动调用写法详见 `agent/README.md`。

工具按风险分三档，**write / exec 一律要在 `input` 里显式传 `confirm:true`**，缺了就返回 `bad_input`。
`confirm` 是给 Agent 的二次确认（防手滑），不是安全边界 —— 它是请求体里的一个值，任何调用方都能自己写；
决定"谁能发出这个请求"的是上面那道令牌闸门。

| 档 | 工具 |
| --- | --- |
| read | `ra.status` `ra.app_state` `ra.window_state` `ra.list_workflows` `ra.get_workflow` `ra.workflow_schema` `ra.validate_workflow` `ra.run_history` `ra.run_status` `ra.draft` `ra.list_secret_refs` |
| write | `ra.save_workflow` `ra.save_draft` `ra.edit_step` `ra.move_step` `ra.remove_step` `ra.add_step` `ra.delete_workflow` `ra.set_secret` `ra.delete_secret` `ra.window_mode` |
| exec | `ra.record_start` `ra.record_stop` `ra.run_workflow` `ra.cancel_run` |

几条不变的边界：秘密值**永不**出现在任何工具的返回里（只有引用名与长度）；`ra.run_workflow` 支持
`wait_s:0` 只发起不等待，之后用 `ra.run_status` 轮询；`from_step` 是人工指定的从失败步续跑；
程序不会自动重试，工具也不会替你重跑动作。

## 结果怎么读

| 结果 | 含义 | 程序会不会重试 |
| --- | --- | --- |
| 完成 | 所有步骤执行完，且设了完成条件的都被验证过 | — |
| 完成 · 未验证 | 步骤执行完了，但有动作没设完成条件，程序没有证据 | 不重试 |
| 未确认 | 动作已发出且**只发出一次**，之后超时/异常/取消，无法判断页面是否生效 | 不重试，停在当前步骤，给出人工检查清单 |
| 失败 | 在动作发生**之前就**停了（目标缺失、匹配多个元素、来源变化、缺秘密值） | 没有点击任何元素 |
| 已取消 | 你点了停止 | 停在当前步骤 |

程序重启后不会根据日志自动续跑；日志只记录事实，不反写工作流。「从失败步重试」是你手动点的那一下，
不是自动重试。从运行历史打开一个已经结束的运行，结果按日志里最后那条终态事件读；日志里读不到终态
就如实写「无记录」，不会替你判成成功。

## 首版边界（界面里也写明了）

- 单个标签页、单个来源（origin）；跨站登录、验证码、文件上传、拖拽、浏览器工具栏操作不在范围内。
- 动作类型：`click`、`fill`（含下拉选择）、`hotkey`、`wait_for`。
- 不退化成屏幕坐标定位；多匹配必须人工选定并重新校验后才允许保存。
- 录制时不保存原始按键流；候选事件来自页面脚本，因此必须经人工审阅才写入工作流。
- 停止按钮在**当前动作返回后**生效：阻塞在浏览器内部的调用无法被策略层打断（每步都有超时上限兜底）。

## 自检与验证

| 目的 | 命令 / 入口 |
| --- | --- |
| 界面与桥接（真实窗口，含窗口形态与 Agent 屏） | `录放台.exe --verify` 或 `python -m ra.main --verify [地址]` |
| **每一个按钮点一遍**（可见、没被挡住、点了真的有反应） | `python -m ra.main --audit`，明细写 `%LOCALAPPDATA%\RecordedAutomation\audit-report.json` |
| 后端链路（真实浏览器 + 本地站点） | `录放台.exe --selfcheck`、`python -m ra.main --selfcheck`，或设置页按钮 |
| 单元与契约测试 | `python -m unittest discover -s tests -t .` |
| 窗口摆放排查 | `%LOCALAPPDATA%\RecordedAutomation\window-debug.txt`（每一步摆放记录都留在这里） |

`--audit` 是给「按钮点不动」这一类缺陷上锁的：它把五个界面里所有可见按钮逐个滚到眼前、
用 `elementFromPoint` 检查中心点是不是真的落在这个按钮上（被别的元素接走就报 `covered`），
再点一次，要求出现可观察变化（界面文本、提示条、确认框、后端调用）；绑了处理器却什么都没发生
判 `noeffect`，什么都没绑判 `dead`，点击后脚本抛错判 `throws`。会改数据、开浏览器、动窗口的调用
由体检层拦下，所以它可以在你自己的机器上反复跑，不会留下副作用。
录制 / 审阅 / 运行三屏是状态驱动的（侧栏没有入口），由 `--verify` 走完整流程时检查。

界面自检会在真实窗口里检查标题条、三种窗口形态的双向切换（含点设置页按钮的真实用户路径）、
拖动与缩放手势、像素级复核 `drift=0`、八个界面、确认框、录制开始/停止、保存、运行、时间线、
日志、删除与快捷键，并把截图写到 `%LOCALAPPDATA%\RecordedAutomation\ui-shots\`。
启动失败时看 `%LOCALAPPDATA%\RecordedAutomation\startup-error.txt`。

## 数据位置

`%LOCALAPPDATA%\RecordedAutomation\`：`workflows/`、`journal.jsonl`、`secrets.json`、`profile/`（受控浏览器）、
`shell-profile/`（界面窗口）、`exports/`、`settings.json`、`ui-shots/`、`window-debug.txt`。设置页可一键打开该目录。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `ra/core.py` | 平台中立契约与回放策略（Runner 只看协议，不导入浏览器库） |
| `ra/recorder.py` + `ra/ui/record_script.js` | 页面事件桥接、来源复核、候选定位器计数 |
| `ra/normalizer.py` | 候选事件归并成草稿，草稿落为 Workflow v1 |
| `ra/driver.py` | Playwright 适配器：定位、执行、执行前复核来源与唯一性 |
| `ra/session.py` | 会话协调器：受控浏览器、录制/回放互斥、取消、状态机 |
| `ra/store.py` `ra/journal.py` `ra/secrets.py` | 工作流存储与校验、落盘日志、DPAPI 秘密库 |
| `ra/shell.py` `ra/winframe.py` `ra/engine.py` | 无边框一体化窗口（CDP + Win32 兜底、像素标定）、JS↔Python 桥、引擎选择与回退 |
| `ra/agentapi.py` | 进程内 Agent 接口服务：与界面共用同一套会话与存储 |
| `ra/localguard.py` | 本机服务共用闸门：Host / Origin / Referer / 令牌（两个入口都走这一份判据） |
| `ra/api.py` `ra/ui/` | 界面门面与前端（工作台/录制/审阅/运行/历史/秘密库/Agent 接口/设置） |
| `ra/selfcheck.py` `ra/uiverify.py` `ra/fixture.py` | 端到端自检、窗口内自检、本地测试站点 |
| `agent/` | 独立服务、工具层与 MCP 桥（界面进程内跑的是同一份 `tools.py`） |
| `build/` | 图标与 PyInstaller 配置（`agent/` 与示例都随包一起走） |
